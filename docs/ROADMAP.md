# 功能规划清单（Feature Roadmap）

> 综合 ThreatLocker、Airlock Digital、Google Santa、Red Hat fapolicyd、Microsoft WDAC/Intune 等同类产品，结合本项目当前状态（PoC + MVP 骨架）整理。
> 优先级：P0 = 阻塞/必须；P1 = 高价值；P2 = 增强/差异化。

## 二、功能清单

### A. 白名单闭环（P0，当前唯一阻塞项）

| 功能 | 说明 | 依赖/备注 |
|---|---|---|
| A1 多策略签名 | 用正式签名环境（AppControl Manager / 完整 SDK / 正式证书）给 `.cip` 签名，打通 Allow 放行 | 已有实现（sign-cip.ps1），环境待就绪 |
| A2 放行生效验证 | 强制模式下：允许列表内程序可运行、列表外被拦 | 依赖 A1 |
| A3 策略签名自检 | 安装时检测签名环境可用性，不可用时自动降级 Audit 模式并提示 | — |

### B. 规则引擎增强（P0/P1，对标 Airlock/Santa 的规则粒度）

| 功能 | 说明 | 优先级 |
|---|---|---|
| B1 签名者规则 | 按证书 Subject/发布者允许（如「所有 Microsoft 签名」） | P0 |
| B2 哈希规则增强 | SHA1+SHA256 双哈希、支持多版本积累 | P0 |
| B3 路径/目录规则 | 允许整个目录（如 `C:\Program Files\App\*`） | P1 |
| B4 通配符/元规则 | 类似 Airlock 的 wildcard metarule | P2 |
| B5 规则优先级 | 明确 Deny > Allow、精确规则 > 宽泛规则 | P1 |
| B6 规则冲突检测 | 策略生成前检测重复/冲突规则 | P1 |
| B7 排除项（Exception） | 允许某个已知问题程序的例外 | P1 |
| B8 规则导入/导出 | JSON/CSV，便于批量维护和迁移 | P1 |
| B9 策略模板 | 内置模板：学习基线、最小系统、开发者模式 | P1 |

### C. 审批与流程（P1，对标 ThreatLocker Cyber Hero / Airlock Exception）

| 功能 | 说明 | 优先级 |
|---|---|---|
| C1 用户自助申请 | 被拦程序弹窗提示「申请运行」，请求进入待审批 | P1 |
| C2 多级审批 | 申请人 → 管理员 → 记录（本地单机可简化） | P2 |
| C3 审批记录/历史 | 谁在何时允许了什么，可导出 | P1 |
| C4 审批通知 | 系统通知/托盘气泡（离线场景） | P2 |
| C5 临时允许 | 允许「本次运行」或限时允许（如 24 小时） | P2 |

### D. 审计与报表（P1）

| 功能 | 说明 | 优先级 |
|---|---|---|
| D1 审计筛选/搜索 | 按时间、程序、事件类型过滤 | P1 |
| D2 拦截趋势图表 | 按天/小时统计拦截数量 | P2 |
| D3 导出报告 | CSV/HTML 报告（合规用） | P1 |
| D4 审计保留策略 | 滚动保留 N 天，自动清理 | P2 |
| D5 告警规则 | 特定程序被拦时高亮/通知 | P2 |

### E. 集中管理与多终端（P1/P2，对标 ThreatLocker/Airlock 控制台）

| 功能 | 说明 | 优先级 |
|---|---|---|
| E1 多终端注册 | Agent 向中心注册，控制台统一管理 | P2（需要服务端） |
| E2 策略下发 | 中心生成策略 → 下发终端 → 终端回执 | P2 |
| E3 策略版本历史 | 每次变更保存版本，支持回滚到任意版本 | P1（单机可做） |
| E4 角色权限（RBAC） | 管理员/审计员/只读 | P2 |
| E5 域/Entra 集成 | 与 AD/Entra 账号对接 | P2 |
| E6 MSP 多租户 | 租户隔离、批量管理 | P2 |

### F. 围栏与加固（P2，对标 ThreatLocker Ringfencing）

| 功能 | 说明 | 依赖 |
|---|---|---|
| F1 应用网络围栏 | WFP 用户态按进程控出站连接（无需驱动） | 可行 |
| F2 子进程限制 | Job Object 限制派生进程 | 可行 |
| F3 提权控制 | UAC 提权审批/受限提权 | 可行 |

| F6 注入防护 | 需 ObRegisterCallbacks（暂缓） | 驱动/签名 |

### G. 运维与分发（P1）

| 功能 | 说明 | 优先级 |
|---|---|---|

| G2 自动更新 | Agent 检查版本并安全升级（离线包） | P2 |
| G3 健康检查 | 服务状态、策略一致性自检 | P1 |
| G4 卸载清理 | 完整卸载（服务、目录、策略） | P1 |
| G5 日志轮转 | 防止日志无限增长 | P2 |

### H. 差异化与前瞻（P2）

| 功能 | 说明 |
|---|---|
| H1 家庭版兜底 | 用 SRP/软件限制策略做降级方案 |
| H2 智能规则建议 | 基于学习数据聚类，推荐「哪些程序应加白」 |
| H3 规则库共享 | 社区/企业共享规则包（离线签名包） |

## 四、关键结论

1. **P0 只有一件事**：签名 + 放行闭环。其余功能都建立在「能拦能放」的基础上。
2. 规则粒度（签名者/路径/目录）是**性价比最高**的增强——Airlock/Santa 的核心竞争力就在规则表达的丰富度。
3. 围栏（F 类）是 ThreatLocker 的差异化，但需要驱动层投入，建议放 v0.5 后。
4. 集中管理（E 类）是产品化的分水岭，建议在单机版稳定后再做服务端。
